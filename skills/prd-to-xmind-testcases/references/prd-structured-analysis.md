# PRD 结构化分析

## 目标

在生成测试点和测试用例之前，先把 PRD 解析成稳定、可复用的系统建模结果。
这一步不是输出格式约束，而是测试设计的输入建模。

本文件禁止使用具体业务实体作为分析框架。
必须先把 PRD 抽象成以下 6 大建模维度，再映射回 PRD 原始术语：

- Domain Model
- State Machine
- Behavior Model
- Data Rules
- Permission Model
- System Behavior

同时必须保持对后续 `testpoint` / `testcase` 阶段的兼容性，结构化分析中仍需保留并明确表达：

- 对象
- 状态
- 行为
- 规则
- 依赖

## 强制分析输出

使用此 skill 时，必须先得到一份结构化分析结果，并通过 `file-system-mcp` 的 `write_file` 落盘到 `./<delivery-name>/analysis/structured-analysis.md`。
该结果至少应包含以下内容：

- PRD 基本信息
- 系统识别
- 版本识别
- 模块拆分
- Domain Model
- State Machine
- Behavior Model
- Data Rules
- Permission Model
- System Behavior
- 状态流转
- 权限边界
- 外部依赖与上下游
- 异步或延迟机制
- 失败与回滚机制
- 边界与极端情况
- 完整性检查
- 歧义点与缺失点

## 强制建模问题（升级版）

在进入测试点建模之前，必须明确回答以下问题：

1. 核心对象及其生命周期
2. 状态机完整性（含非法迁移）
3. 行为语义（含副作用）
4. 数据约束（含跨字段）
5. 权限控制维度
6. 异步/依赖/事务机制
7. 失败补偿与幂等机制
8. 边界与极端情况

如果以上任一问题无法回答：

- 优先补充结构化分析
- 或明确标注 `PRD未说明`
- 不要直接跳到写测试用例

## 完整性约束

在 analysis 阶段，必须执行覆盖性检查。
禁止跳过以下检查项：

- 状态是否完整
- 行为是否完整
- 数据规则是否完整
- 权限是否完整
- 异常路径是否完整

如果任一检查项不完整，必须执行以下动作之一：

- 基于 PRD 文本、图片结构化结果、PlantUML、上下游关系进行补充推断，并标注为 `推断`
- 无法推断时标记为 `PRD未说明`

禁止因为 PRD 未直接说明而跳过建模。
禁止把不完整项静默遗漏。

## 推荐分析框架

建议按以下顺序分析 PRD：

### 1. 文档基础信息

提取：

- 文档标题
- 修订时间
- 需求背景
- 业务目标
- 上下游系统
- 是否存在图片、流程图、时序图、原型图

输出建议：

- PRD 名称
- 背景摘要
- 目标摘要

### 2. 系统与边界识别

明确：

- 当前测试树属于哪个系统
- 是否存在跨系统联动
- 哪些能力属于主系统
- 哪些能力属于外部系统或依赖系统

输出建议：

- 主系统
- 外部依赖系统
- 数据来源系统
- 结果承接系统
- 消息触达系统

### 3. 模块拆分

模块必须从稳定的能力边界出发，而不是只看页面标题。

优先拆分依据：

- 功能列表中的能力块
- 行为边界
- 流程阶段
- 菜单结构
- 对象边界
- 规则边界
- 权限边界
- 事务或异步边界

模块拆分后，每个模块都应至少补齐：

- 模块目标
- 核心对象
- 核心行为
- 关键状态
- 关键规则
- 权限边界
- 系统行为边界

## Domain Model

识别所有测试相关领域对象。
不要一开始就沉迷于领域名词，应先抽象对象类型，再在最终用例阶段映射回原词。

### 对象

每个对象必须补齐：

- 对象标识
- PRD 原始术语
- 类型（主体 / 资源 / 关系 / 配置 / 结果）
- 关键属性
- 生命周期
- 上下游关系
- 是否持久化
- 与其他对象的关系
- 关联状态
- 关联行为
- 关联规则

对象类型定义：

- 主体：发起行为或承载权限的用户、角色、组织、系统账号
- 资源：被创建、查询、更新、删除、流转、消费的业务对象
- 关系：连接主体与资源、资源与资源、系统与系统的映射或绑定
- 配置：影响行为、规则、权限、流程、策略的可变参数
- 结果：行为执行后产生的记录、消息、状态、报表、任务、事件

生命周期至少包含：

- 创建前
- 创建中
- 已创建
- 使用中或处理中
- 已完成或已生效
- 已失效、已关闭或已归档

若 PRD 未说明生命周期，必须标记 `PRD未说明`，并在完整性检查中记录。

## State Machine

从 PRD 中提取所有显式或隐式状态，但先使用通用状态概念，不要被领域词绑定。

例如可抽象为：

- 初始
- 已创建
- 待处理
- 处理中
- 已完成
- 已生效
- 待失效
- 已失效
- 已取消
- 已关闭
- 已恢复
- 失败

### 状态列表

每个状态必须补齐：

- 状态标识
- PRD 原始术语
- 所属对象
- 进入条件
- 退出条件
- 可执行行为
- 不允许行为
- 关联通知
- 是否终态
- 是否可恢复

### 状态迁移矩阵

必须用矩阵或等价结构表达状态迁移：

- 起始状态
- 目标状态
- 触发行为
- 前置条件
- 处理结果
- 副作用
- 是否允许
- PRD 依据

### 非法迁移

必须识别非法迁移：

- 起始状态
- 目标状态
- 触发行为
- 禁止原因
- 期望系统响应
- 错误提示或失败结果

若 PRD 未说明非法迁移的响应方式，标记 `PRD未说明`。

### 状态幂等性

必须分析同一状态下重复执行同一行为的结果：

- 重复提交
- 重复取消
- 重复回调
- 重复同步
- 重复通知
- 重复重试

输出必须标注：

- 保持原状态
- 产生新结果
- 返回已有结果
- 拒绝操作
- PRD未说明

### 并发状态

必须识别状态并发风险：

- 同一对象被多人同时操作
- 同一对象被多个系统同时更新
- 异步任务与人工操作并发
- 回调与主动查询并发
- 定时任务与实时行为并发

若 PRD 未说明并发处理机制，标记 `PRD未说明`。

## Behavior Model

必须先抽出主流程，再考虑异常和分支。

每个行为必须拆成：

- 输入
- 前置条件
- 处理逻辑
- 副作用（必须）
- 输出

行为类型可抽象为：

- 创建
- 查询
- 更新
- 删除
- 触发
- 同步
- 审批
- 通知
- 导入
- 导出
- 关闭
- 恢复
- 取消
- 重试
- 补偿

每条行为至少补齐：

- 行为标识
- PRD 原始术语
- 所属模块
- 发起主体
- 操作对象
- 输入
- 前置条件
- 处理逻辑
- 副作用（必须）
- 输出
- 触发的状态变化
- 触发的数据变化
- 触发的外部依赖
- 成功路径
- 失败路径
- 幂等要求
- 并发影响

副作用必须显式分析，例如：

- 创建记录
- 修改状态
- 写入日志
- 发送通知
- 触发异步任务
- 调用外部系统
- 更新缓存
- 生成结果对象
- 影响权限范围
- 影响后续流程

如果 PRD 同时有正文与流程图：

- 正文负责规则
- 流程图负责顺序、节点、分支
- PlantUML 负责结构化路径校验
- 三者冲突时正文优先，并在歧义点记录冲突

## Data Rules

识别所有输入、处理、结果与跨字段规则。
每条规则都必须判断规则类型、触发位置和验证结果。

必须拆为：

- 输入约束
- 业务规则
- 结果约束
- 跨字段约束
- 时间约束
- 幂等约束

### 输入约束

识别：

- 必填项
- 数据类型
- 长度限制
- 格式限制
- 枚举值
- 默认值
- 取值来源
- 为空处理
- 非法值处理

### 业务规则

识别：

- 唯一性规则
- 去重规则
- 计算规则
- 匹配规则
- 优先级规则
- 排序规则
- 搜索规则
- 分页规则
- 导入导出规则
- 生效失效规则

### 结果约束

识别：

- 输出字段
- 结果状态
- 结果数量
- 结果可见性
- 结果一致性
- 结果持久化
- 结果通知
- 结果回传

### 跨字段约束

识别：

- 字段互斥
- 字段依赖
- 字段联动
- 字段组合唯一
- 字段取值范围关联
- 字段与状态关联
- 字段与权限关联

### 时间约束

识别：

- 生效时间
- 失效时间
- 截止时间
- 延迟时间
- 定时执行
- 超时处理
- 时间窗口
- 跨日、跨月、跨时区

### 幂等约束

识别：

- 幂等键
- 唯一请求标识
- 重复提交处理
- 重复回调处理
- 重复消息处理
- 重试结果一致性
- 历史结果复用

## Permission Model

权限分析必须覆盖身份、操作、数据范围和时间维度。

必须包含：

- 身份权限
- 操作权限
- 数据范围权限
- 时间权限

### 身份权限

识别：

- 用户
- 角色
- 组织
- 岗位
- 系统身份
- 外部系统身份
- 匿名或未登录身份

### 操作权限

识别：

- 谁可查看
- 谁可新增
- 谁可修改
- 谁可删除
- 谁可审批
- 谁可导入
- 谁可导出
- 谁可触发
- 谁只读
- 谁不可操作

### 数据范围权限

识别：

- 本人数据
- 本部门数据
- 下级组织数据
- 指定门店或业务单元数据
- 全量数据
- 跨系统数据
- 敏感字段可见性
- 结果数据可见性

### 时间权限

识别：

- 指定时间窗口内可操作
- 超时后不可操作
- 生效前不可操作
- 失效后不可操作
- 定时任务窗口
- 非工作时间限制
- PRD未说明

## System Behavior

系统行为用于识别单个功能背后的运行机制，必须强制分析：

- 同步 / 异步
- 事务边界
- 重试机制
- 幂等机制
- 失败补偿
- 外部依赖 SLA

### 同步 / 异步

识别：

- 同步返回
- 异步处理
- 定时任务
- 延迟触发
- 消息队列
- 外部回调
- 前端轮询
- 后台批处理

必须标注：

- 触发时机
- 执行方
- 完成判定
- 用户可见结果
- 超时表现

### 事务边界

识别：

- 单对象事务
- 多对象事务
- 跨系统事务
- 最终一致性
- 部分成功
- 回滚范围
- 提交点
- 不可回滚副作用

若 PRD 未说明事务边界，标记 `PRD未说明`。

### 重试机制

识别：

- 自动重试
- 手动重试
- 定时重试
- 回调重试
- 消息重试
- 最大重试次数
- 重试间隔
- 重试终止条件

### 幂等机制

识别：

- 请求幂等
- 状态幂等
- 消息幂等
- 回调幂等
- 任务幂等
- 结果幂等
- 幂等键来源
- 重复请求返回策略

### 失败补偿

识别：

- 回滚
- 撤销
- 冲正
- 重新同步
- 人工处理
- 告警
- 失败记录
- 死信或异常队列
- 通知用户

### 外部依赖 SLA

识别：

- 依赖系统
- 调用方式
- 超时时间
- 可用性要求
- 限流策略
- 降级策略
- 数据一致性要求
- 依赖失败后的用户表现

## 边界与极端情况

必须识别：

- 空数据
- 单条数据
- 大批量数据
- 最大长度
- 最小长度
- 特殊字符
- 重复数据
- 过期数据
- 删除后数据
- 已失效数据
- 并发操作
- 网络失败
- 外部系统超时
- 权限变化
- 状态变化后继续操作
- 时间边界

## 缺失与待确认识别

结构化分析的最后，必须收敛出：

- PRD 明确说明
- 可合理推断
- 无法推断
- 存在冲突
- PRD未说明

这一步直接决定后续哪些测试点能生成、哪些只能进入 `待确认项`。
